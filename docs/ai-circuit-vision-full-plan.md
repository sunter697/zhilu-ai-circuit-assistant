## 1. 文档目标

本文档定义 Logisim Evolution AI 电路图识别功能的完整工程方案。目标是让用户选择一张电路图，软件识别其中的
元件、导线和连接关系，经用户确认后，将其重建为可编辑、可仿真、可整体撤销的 Logisim 电路。

方案采用“小型目标检测模型 + 确定性图像处理 + Logisim 原生电路构建”的混合架构。模型不直接生成 `.circ`
文件，也不通过大量不可控的 AI 工具调用修改当前电路。

## 2. 总体原则

1. 视觉模型只负责感知，不负责直接修改项目。
2. 图片识别结果必须先转换成版本化的 Vision IR。
3. Vision IR 必须经过语法、几何和拓扑校验。
4. 电路先在隔离工作区重建和验证，用户确认后再应用。
5. 导入默认创建新电路，不覆盖用户当前电路。
6. 一次图片导入只产生一个撤销动作。
7. 所有不确定判断必须显式记录，不能静默猜测。
8. 检测器、导线提取器和运行方式必须可替换。

### 3.1 第一阶段正式支持

- 元件旋转和多种缩放比例。
- 总线、分线器、隧道和常量。

## 5. 技术选型

### 5.1 模型训练

- 使用 Python 完成数据处理、训练、评估和 ONNX 导出。
- 检测器通过统一接口接入，避免业务代码绑定具体模型品牌。
- 发布版本优先选择许可证适合开源分发的小型检测器，例如 YOLOX-Nano。
- 如果原型阶段使用 Ultralytics，应在分发代码和权重前完成许可证审查。
- 模型只检测元件主体，不检测导线和连接点。

检测类别：

```text
INPUT_PIN
OUTPUT_PIN
AND
OR
NOT
NAND
NOR
XOR
XNOR
```

### 5.2 运行时

完整版目标运行时为 Java：

- ONNX Runtime Java 执行模型推理。
- Java 完成 letterbox、归一化、后处理和 NMS。
- Java 导线提取器处理严格正交的 Logisim 导线。
- 训练所需的 Python 不作为最终用户的必需依赖。

开发阶段可以保留 Python HTTP 服务作为基准实现和调试工具，但不能成为最终架构的唯一实现。

### 5.3 导线识别

Logisim 的 V1 导线是正交的，因此优先采用确定性算法：

1. 灰度化和自适应阈值分割。
2. 根据元件主体框遮挡元件内部线条。
3. 保留端口附近的短线段。
4. 水平和垂直游程扫描。
5. 合并共线、相邻或轻微断裂的线段。
6. 估算网格尺寸和网格原点。
7. 将端点吸附到网格。
8. 求交点、端点和 T 形连接。
9. 通过像素圆点和拓扑约束判断 junction。
10. 使用并查集构建 net。

junction 不作为目标检测类别。它尺寸太小，并且其语义由多条线段共同决定。

## 6. Vision IR 0.1

Vision IR 是识别模块和电路构建模块之间的稳定契约。一周版和完整版必须共享这一契约；一周版可以不填写可选字段，
但不能使用另一套不兼容的数据格式。

### 6.1 示例

```json
{
  "schemaVersion": "vision-ir/0.1",
  "source": {
    "sha256": "...",
    "width": 1600,
    "height": 900
  },
  "profile": {
    "theme": "light",
    "gateShape": "ansi",
    "gridPixels": 10.0,
    "scale": 1.0,
    "offsetX": 4.0,
    "offsetY": 7.0
  },
  "components": [
    {
      "id": "c1",
      "kind": "AND",
      "bodyBox": [420, 210, 486, 254],
      "anchor": [460, 230],
      "facing": "EAST",
      "attributes": {
        "inputs": 2,
        "bitWidth": 1
      },
      "ports": [
        {"id": "in0", "direction": "INPUT", "point": [420, 220]},
        {"id": "in1", "direction": "INPUT", "point": [420, 240]},
        {"id": "out", "direction": "OUTPUT", "point": [490, 230]}
      ],
      "confidence": 0.97
    }
  ],
  "nets": [
    {
      "id": "n1",
      "endpoints": [
        {"componentId": "c1", "portId": "in0"}
      ],
      "segments": [
        [200, 220, 420, 220]
      ],
      "junctions": [],
      "confidence": 0.94
    }
  ],
  "unresolved": [],
  "semanticHash": "..."
}
```

### 6.2 契约要求

- `schemaVersion` 必须存在，解析器拒绝未知主版本。
- `source` 保存摘要和尺寸，不保存用户本地绝对路径。
- `kind` 是视觉语义枚举，不直接保存 Java 类名。
- 图片坐标、网格坐标和电路坐标必须明确区分。
- 每个元件、net 和不确定项具有独立置信度。
- ID 在单份 IR 中必须唯一且稳定。
- 所有 endpoint 必须引用存在的元件和端口。
- `unresolved` 保存无法可靠确定的元件、导线和冲突。
- `semanticHash` 只反映电路语义，不包含图片布局。
- `layoutHash` 可以作为后续可选字段保存布局信息。

### 6.3 拓扑等价规则

- AND、OR、NAND、NOR、XOR、XNOR 的输入端口交换视为等价。
- NOT 的输入和输出方向不可交换。
- net 作为端点集合比较，不依赖线段顺序。
- 几何折线路径不同但连接关系相同，语义上视为等价。
- 元件类型、关键属性和 netlist 共同参与 semantic hash。

## 8. 端口匹配策略

模型不直接预测端口坐标。流程如下：

1. 模型输出元件类别和主体框。
2. `GridEstimator` 计算统一缩放和网格偏移。
3. `ComponentTemplateCatalog` 根据类型、朝向和输入数量推导候选锚点。
4. 在隔离工作区临时创建真实 Logisim 元件。
5. 从 Logisim 元件对象读取真实端口位置。
6. `PortMatcher` 将导线端点吸附到这些真实端口。
7. 如果多个端口同样合理，产生 `unresolved`，等待用户确认。

该方法能够避免检测框几像素误差导致视觉上相连、实际却没有电气连接的问题。

## 9. 数据集生成

### 9.1 原生生成流程

1. 随机生成合法的组合逻辑 DAG。
2. 分配输入、门和输出。
3. 保证每个门最终到达至少一个输出。
4. 按拓扑深度分层布局。
5. 使用真实 Logisim factory 创建元件。
6. 使用安全布线器创建正交导线。
7. 通过 Logisim 原生绘制链路生成 PNG。
8. 从电路对象导出元件主体框、锚点、端口、导线和 netlist。
9. 计算 semantic hash。
10. 输出 YOLO 标注、Vision IR 和生成元数据。

### 9.2 数据划分

- 相同 semantic hash 的所有渲染变体只能出现在同一个数据分组。
- 训练集、验证集和测试集按拓扑分组划分。
- 测试集中必须包含人工创建的真实 Logisim 图片。
- 保存随机种子、代码提交、主题、门形状、缩放和裁剪变换。

### 9.3 生成节奏

1. 先生成 500 张。
2. 自动检查每张图片的标注和拓扑。
3. 人工抽查至少 50 张。
4. 修复生成器后扩大到 5000 至 10000 张。
5. 训练后收集失败样本，定向补充难例。

## 10. 用户交互

### 10.1 助手入口

在 AI 助手输入区增加“识别电路图”入口。用户选择图片后，显示缩略图、运行状态和取消按钮。

### 10.2 结果摘要

识别完成后显示：

- 元件数量和分类统计。
- net 数量。
- 低置信度元件数量。
- 未连接端口和冲突数量。
- “检查结果”“应用到新电路”“取消”操作。

### 10.3 检查界面

覆盖层建议使用以下颜色：

- 绿色：通过校验且置信度充足。
- 黄色：需要用户确认。
- 红色：拓扑冲突或无法导入。

用户可以修改元件类别、移动锚点、删除误检元件、重新连接端口和忽略非电路图形。修改后重新运行拓扑校验。

### 10.4 AI 助手的职责

AI 助手可以解释问题、总结识别结果和提出修正建议，但不直接绕过 Vision IR 和导入验证。只有当所选模型端点明确支持图像输入时，
才将局部裁剪交给多模态模型辅助判断。

## 11. 构建、验证和应用

### 11.1 CircuitImportPlan

`CircuitImportPlanner` 将 Vision IR 转换为内部计划。计划应包含：

- 目标电路名称。
- Logisim factory 身份。
- 元件锚点和属性。
- 真实端口映射。
- Wire 段集合。
- 来源 IR 摘要。
- 预期 semantic hash。
- 所有警告和未解决项。

### 11.2 隔离构建

- 使用现有工作区能力复制项目状态。
- 在隔离工作区执行 `CircuitImportBuilder`。
- 不对用户当前项目执行增量试错。
- 构建失败时丢弃隔离结果。

### 11.3 结构验证

`StructuralImportVerifier` 至少检查：

- 元件 factory 和属性是否符合计划。
- 元件是否位于合法网格。
- 是否发生非法重叠。
- Wire 是否连接到真实端口。
- 是否存在意外短接或悬空端点。
- 实际 netlist 是否与计划语义等价。
- 实际 semantic hash 是否匹配。

### 11.4 功能验证

对输入总位数不大的组合逻辑电路，可以枚举输入并比较原 Vision IR 推导的逻辑与重建电路输出。功能验证是结构验证的补充，
不能替代结构验证。

### 11.5 应用和撤销

- 用户确认前不修改当前项目。
- 整个导入作为一个项目动作记录。
- 应用失败时自动回滚。
- 用户执行一次撤销即可删除整次导入。

## 12. 测试策略

### 12.1 Java 单元测试

- Vision IR JSON 往返测试。
- 未知版本、重复 ID、非法坐标和悬空引用测试。
- 手写 IR 到电路的导入测试。
- 元件属性和端口映射测试。
- 拓扑 canonicalization 测试。
- 可交换输入端口的等价测试。
- 整体应用和整体撤销测试。

### 12.2 视觉算法测试

- 每类元件 Precision 和 Recall。
- 不同缩放、边距和压缩下的检测表现。
- 线段、端点和 junction 的独立指标。
- 端口匹配正确率。
- net Precision 和 Recall。
- 整图 exact graph match。

### 12.3 集成测试

- 选择图片、取消识别和超时。
- 模型文件缺失或损坏。
- 空图片和非电路图片。
- 不支持的电路元素。
- 识别失败后原项目不变。
- 导入后电路可仿真并可整体撤销。

## 13. 验收指标

完整版第一阶段建议达到：

- 各元件类别 Recall 不低于 98%。
- 端口匹配正确率不低于 99%。
- net F1 不低于 98%。
- junction F1 不低于 95%。
- 受支持测试集的整图 exact graph match 不低于 90%。
- 用户检查修正后的成功重建率不低于 98%。
- 25 个元件以内的典型图片，在参考 CPU 上 5 秒内完成识别。
- 失败、取消和超时时不修改用户项目。

### 阶段 A：契约与导入核心

## 15. 主要风险和对策

### 15.1 元件识别正确但整图仍错误

检测指标不能代替拓扑指标。以 exact graph match 作为核心指标，并独立测试端口匹配和 net 构建。

### 15.2 反相圆点和 junction 太小

根据原始图片中最小特征的像素尺寸决定输入分辨率，必要时使用高分辨率推理或分块推理，不能预先固定为 640。

### 15.3 数据泄漏

以 semantic hash 分组，确保同一电路的不同渲染不会跨越训练集和测试集。

### 15.4 原生库打包复杂

最终运行时只保留 ONNX Runtime 这一类必要原生依赖，导线处理尽量使用纯 Java。逐个平台验证安装包。

### 15.5 模型或框架许可证

在训练和分发权重前记录框架、基础权重、训练脚本和模型文件的许可证。模型品牌不得写死在业务协议中。

## 16. 与一周版的演进关系

一周版不是一次性原型。只要遵守以下边界，就可以直接演进为完整版：

1. 一周版使用同一个 `vision-ir/0.1`，只是只填写字段子集。
2. Python 识别服务位于 `VisionRecognizer` 或 `VisionServiceClient` 接口后面。
3. Java 导入器只依赖 Vision IR，不依赖 Python、YOLO 或图片文件。
4. `CircuitImportPlan`、builder 和 verifier 从第一天开始独立存在。
5. 一周版默认导入新电路，不把识别过程写入当前电路。
6. 元件视觉类型通过映射转换为 factory，不在 JSON 中保存 Java 类名。
7. 测试图片、手写 IR 和集成测试继续作为完整版回归集。

升级时需要替换或增强的是检测实现、数据生成方式、审核界面和部署方式；导入核心、IR 和大部分测试可以原样保留。

## 17. 完成定义

功能只有在满足以下条件后才视为完成：

- 用户可以选择图片并取消识别。
- 支持范围内的图片可以输出有效 Vision IR。
- 用户可以查看和修正不确定项。
- 重建发生在隔离工作区。
- 结构验证通过后才能应用。
- 导入电路可编辑、可仿真、可整体撤销。
- 失败、取消和异常不会损坏当前项目。
- 训练、评估、模型信息和使用限制都有文档记录。
